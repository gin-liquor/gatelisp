RustでHLispコンパイラの最初の段階となる、S式Reader／Parserを実装してください。
まず現在のリポジトリを確認し、既存コードがあれば尊重してください。その後、以下の仕様に従って実装、テスト、動作確認まで行ってください。
今回の目的
HLispソースを汎用的なS式ASTへ変換できる最小パーサを作成します。
今回の実装では、module、ports、assignなどのHLisp固有の意味解析は行いません。これらはすべて通常のSymbolとして読み取ってください。
対応する構文
以下に対応してください。
•	左括弧 (
•	右括弧 )
•	シンボル
•	キーワード
•	符号付き10進整数
•	文字列
•	;から行末までのコメント
•	空白、タブ、CRLF、LF
例：
(module and-gate
  (ports
    (a :in bit)
    (b :in bit)
    (y :out bit))

  (assign y (and a b)))
AST
次の構造を基本としてください。必要なら実装上の微調整は構いませんが、設計意図は維持してください。
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Position {
    pub offset: usize,
    pub line: usize,
    pub column: usize,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Span {
    pub start: Position,
    pub end: Position,
}

#[derive(Debug, Clone, PartialEq)]
pub struct Spanned<T> {
    pub value: T,
    pub span: Span,
}

#[derive(Debug, Clone, PartialEq)]
pub enum SExpr {
    List(Vec<Spanned<SExpr>>),
    Symbol(String),
    Keyword(String),
    Integer(i64),
    String(String),
}
行番号と桁番号は、人間向けには1から始まるようにしてください。
offsetはUTF-8バイト位置として扱うか文字位置として扱うかを実装内で統一し、その判断をREADMEに記載してください。
Lexer
LexerとParserを分離してください。
トークンは概ね次の種類を持つものとします。
pub enum TokenKind {
    LeftParen,
    RightParen,
    Symbol(String),
    Keyword(String),
    Integer(i64),
    String(String),
    Eof,
}
各TokenはSpanを保持してください。
処理規則：
1.	空白を読み飛ばす
2.	;から行末までをコメントとして読み飛ばす
3.	(をLeftParenとして読む
4.	)をRightParenとして読む
5.	"から文字列を読む
6.	その他はatomとして読み、整数、キーワード、シンボルに分類する
atomの区切りは、空白、括弧、コメント開始文字、EOFです。
分類規則：
•	:inはKeyword "in"
•	:だけの場合はエラー
•	123はInteger
•	-45はInteger
•	-はSymbol
•	+はSymbol
•	and-gateはSymbol
•	state?はSymbol
文字列
最低限、以下のエスケープに対応してください。
•	\"
•	\\
•	\n
•	\r
•	\t
未対応のエスケープはエラーにしてください。
閉じられていない文字列もエラーにしてください。
Parser
再帰下降方式で実装してください。
入力全体に複数のS式が並んでいても解析できるようにし、公開APIは概ね次の形にしてください。
pub fn parse_document(
    source: &str,
) -> Result<Vec<Spanned<SExpr>>, ParseError>;
必要ならLexer用の公開APIも用意してください。
エラー
エラーは少なくとも次の情報を保持してください。
•	エラーメッセージ
•	Span
•	エラー種別
最低限、次のエラーを検出してください。
•	予期しない右括弧
•	閉じられていないリスト
•	閉じられていない文字列
•	不正な文字列エスケープ
•	空のキーワード
•	i64の範囲を超えた整数
閉じられていないリストでは、対応する左括弧のSpanを示してください。
ライブラリ内部ではpanicを使わず、Resultでエラーを返してください。ただし、テストコード内のunwrapは使用可能です。

CLI
次の形式でファイルを解析できる簡単なCLIを作ってください。
cargo run -- examples/and_gate.hlisp
成功時はASTを整形して標準出力へ表示してください。
失敗時は、ファイル名、行、桁、エラーメッセージを標準エラー出力へ表示し、終了コードを非ゼロにしてください。
