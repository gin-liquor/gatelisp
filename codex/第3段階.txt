GateLispコンパイラの第3段階として、名前解決、型検査、Typed HIR生成を実装してください。
作業開始前に、現在のリポジトリ全体、AGENTS.md、S式Reader、GateLisp固有AST、既存テスト、READMEを確認してください。
既存のReader APIおよびGateLisp AST Parser APIを維持してください。既存テストを壊さないでください。
コミットおよびpushは行わず、実装、テスト、動作確認まで行ってください。
今回の目的
現在のコンパイラ構成：
GateLisp source
→ Lexer
→ S-expression AST
→ GateLisp AST
今回、次を追加します。
GateLisp source
→ Lexer
→ S-expression AST
→ GateLisp AST
→ name resolution
→ type checking
→ Typed HIR
今回はVHDL AST、VHDL生成、クロック回路、FSM、モジュールインスタンス、マクロは実装しません。
基本方針
GateLisp ASTはソース構文を表します。
Typed HIRは、以下が確定したハードウェア表現としてください。
•	すべての信号参照がSignalIdへ解決済み
•	すべての式の型が確定済み
•	組み込み演算子がenumへ変換済み
•	代入先がSignalIdへ解決済み
•	不正な宣言や式は排除済み
•	生の文字列名による参照を残さない
GateLisp ASTから直接VHDLを生成しないでください。
ハードウェア型
GateLisp ASTの型から、意味解析用のハードウェア型へ変換してください。
概ね次の型を想定します。
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum HardwareType {
    Bit,
    Unsigned(u32),
    Signed(u32),
}
必要ならCopyやHashを追加して構いません。
型の等価性は完全一致としてください。
以下は異なる型です。
bit
(unsigned 1)
(signed 8)
(unsigned 8)
(unsigned 16)
ID
名前解決後は文字列名ではなくIDを使用してください。
概ね次の構造を想定します。
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct ModuleId(pub u32);

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct SignalId(pub u32);
IDの内部型はusizeなどに変更して構いません。
IDは少なくとも各Program内で安定して一意になるようにしてください。
Typed HIR
正確な名称や配置は既存コードへ合わせて構いませんが、概ね次の情報を持たせてください。
pub struct TypedProgram {
    pub modules: Vec<TypedModule>,
}

pub struct TypedModule {
    pub id: ModuleId,
    pub name: String,
    pub name_span: Span,
    pub signals: Vec<TypedSignal>,
    pub assignments: Vec<TypedAssign>,
    pub span: Span,
}

pub struct TypedSignal {
    pub id: SignalId,
    pub name: String,
    pub kind: SignalKind,
    pub ty: HardwareType,
    pub declaration_span: Span,
}

pub enum SignalKind {
    Input,
    Output,
    Wire,
    Register {
        initial: Option<TypedExpr>,
    },
}

pub struct TypedAssign {
    pub target: SignalId,
    pub value: TypedExpr,
    pub span: Span,
}

pub struct TypedExpr {
    pub kind: TypedExprKind,
    pub ty: HardwareType,
    pub span: Span,
}

pub enum TypedExprKind {
    Signal(SignalId),
    Integer(i64),
    Unary {
        op: UnaryOp,
        operand: Box<TypedExpr>,
    },
    Binary {
        op: BinaryOp,
        left: Box<TypedExpr>,
        right: Box<TypedExpr>,
    },
    If {
        condition: Box<TypedExpr>,
        when_true: Box<TypedExpr>,
        when_false: Box<TypedExpr>,
    },
}
必要に応じて、整数値を型付き定数構造へ分離して構いません。
Typed HIRでは、組み込み演算子を文字列のまま保持しないでください。
信号名前空間
各モジュール内で以下を一つの信号名前空間として扱ってください。
•	input port
•	output port
•	wire
•	register
同名宣言は禁止です。
例：
(module invalid
  (ports
    (value :in bit)
    (value :out bit)))
これは重複宣言エラーです。
以下も重複です。
(module invalid
  (ports
    (value :in bit))

  (wire value bit))
名前は大文字・小文字を区別してください。
value
Value
は別名です。
宣言順に依存せず、モジュール内の全宣言を収集してから式を解析してください。
したがって、宣言より前のassignで後に宣言されるwireを参照しても、名前解決上は許可してください。
モジュール名
同一Program内のmodule名重複を検出してください。
今回はモジュールインスタンスがないため、ModuleIdは割り当てますが、モジュール間参照は実装しません。
assign規則
assign先は、存在する信号でなければなりません。
continuous assignを許可する信号：
•	output port
•	wire
continuous assignを禁止する信号：
•	input port
•	register
例：
(assign input-port value)
はエラーです。
(assign register-name value)
もエラーです。
同じoutputまたはwireへ複数のassignがある場合は、複数ドライバエラーにしてください。
未駆動のoutput、wire、registerは今回はエラーにしないでください。
信号参照
式中のSymbolは、同一モジュールの信号として解決してください。
以下を検出してください。
•	未宣言信号
•	宣言名ではあるが信号ではないもの
•	不正な参照
現在は定数宣言、関数、ローカル変数がないため、式中のReferenceはすべて信号参照です。
output portを式から参照することは許可してください。
registerを式から参照することも許可してください。
整数リテラル
整数リテラルはAST段階では型を持たず、意味解析時に周囲の期待型へ適合させてください。
代入例：
(reg count (unsigned 8) 0)
(assign value 255)
型ごとの適合範囲：
bit:
  0 または 1

unsigned N:
  0 ～ 2^N - 1

signed N:
  -2^(N-1) ～ 2^(N-1) - 1
範囲外はエラーです。
例：
(reg x bit 2)
(reg x (unsigned 8) -1)
(reg x (unsigned 8) 256)
(reg x (signed 8) 128)
(reg x (signed 8) -129)
幅が64以上の場合も、シフト演算によるRust側のoverflowやpanicを起こさないようにしてください。
現在の整数リテラルがi64であることを踏まえ、i128などを使って安全に判定してください。新しいBigInt依存は追加しないでください。
暗黙変換
整数リテラルの期待型への適合を除き、暗黙変換は禁止してください。
以下は型エラーです。
bit → unsigned(1)
unsigned(8) → unsigned(16)
signed(8) → unsigned(8)
unsigned(8) → signed(8)
resize、truncate、as-signed、as-unsignedなどの明示変換は今回はまだ実装しません。
組み込み演算子
今回、以下の演算子を意味解析してください。
単項演算
(not value)
notの引数は必ず1個です。
許可する型：
•	bit
•	unsigned N
•	signed N
結果型は入力型と同じです。
ビット論理演算
(and a b)
(or a b)
(xor a b)
各演算子の引数は必ず2個です。
左右は完全に同じ型でなければなりません。
許可する型：
•	bit
•	unsigned N
•	signed N
結果型は入力型と同じです。
ここではベクタに対してはビット単位演算として扱います。
算術演算
(+ a b)
(- a b)
各演算子の引数は必ず2個です。
許可する型：
•	unsigned N
•	signed N
左右は完全に同じ型でなければなりません。
結果型は入力型と同じ型、同じ幅です。
オーバーフロー時の意味は、固定幅ハードウェア上の折り返しとします。定数畳み込みは今回実装しなくて構いません。
bitに対する+と-は禁止してください。
乗算、除算、剰余、シフトは今回は実装しません。
等値比較
(= a b)
(/= a b)
引数は必ず2個です。
左右は完全に同じ型でなければなりません。
bit、unsigned、signedのすべてを許可してください。
結果型はbitです。
順序比較
(< a b)
(<= a b)
(> a b)
(>= a b)
引数は必ず2個です。
左右は完全に同じ型でなければなりません。
unsignedまたはsignedを許可してください。
bitは禁止してください。
結果型はbitです。
if式
(if condition when-true when-false)
引数は必ず3個です。
•	conditionはbit
•	when-trueとwhen-falseは完全に同じ型
•	結果型は分岐式の型
ifは通常の関数呼び出しではなく、Typed HIRでは専用ノードにしてください。
期待型による推論
意味解析関数は、必要に応じて期待型を受け取れる設計にしてください。
概念例：
fn check_expr(
    expr: &Spanned<Expr>,
    expected: Option<&HardwareType>,
    context: &ModuleContext,
) -> Result<TypedExpr, SemanticError>;
具体的なAPIは調整して構いません。
期待型を与える場所：
•	assign右辺：代入先の型
•	register初期値：registerの型
•	ifの分岐：外側の期待型がある場合、その型
•	演算子の整数リテラル引数：他方または外側から確定した型
以下は解析可能にしてください。
(assign output (+ input 1))
(assign output (if select 0 input))
(assign output (if select 0 1))
最後の例はassign先の型を両方の整数リテラルへ伝播してください。
以下のように、どこからも型を決定できない式は型推論エラーにしてください。
(foo 1 2)
ただしfooは今回未知の演算子エラーになるため、少なくともpanicせず適切なエラーにしてください。
比較の両辺が整数リテラルのみで、周囲からもオペランド型が分からない場合も、型推論不能エラーにしてください。
(assign flag (= 1 2))
assign先のbitは比較結果の型であり、比較オペランドの型には使用しないでください。
演算子の引数に整数リテラルがある場合
片方が型付き信号であれば、その型を整数リテラルへ使用してください。
(+ input 1)
(+ 1 input)
(= input 0)
(< count 10)
両方が信号なら型の完全一致を確認してください。
両方が整数リテラルで、外側の期待型を算術演算へ適用できる場合は、その期待型を使用してください。
(assign output (+ 1 2))
ここではoutputの型を+のオペランドと結果へ伝播してください。
比較演算では、結果の期待型bitからオペランド型を推測しないでください。
未知の呼び出し
現在は組み込み演算子以外の関数、マクロ、モジュール呼び出しは存在しません。
したがって、
(foo a b)
は未知の演算子エラーにしてください。
S式ParserおよびGateLisp AST Parserでは任意の呼び出しを受理する既存動作を維持してください。
未知の呼び出しを拒否するのは意味解析段階だけです。
演算子enum
Typed HIRでは演算子をenum化してください。
概ね次の形です。
pub enum UnaryOp {
    Not,
}

pub enum BinaryOp {
    And,
    Or,
    Xor,
    Add,
    Subtract,
    Equal,
    NotEqual,
    LessThan,
    LessEqual,
    GreaterThan,
    GreaterEqual,
}
名称はRustとして読みやすい形へ調整して構いません。
register初期値
register初期値はregister自身の型を期待型として型検査してください。
(reg count (unsigned 8) 0)
初期値なしも許可してください。
初期値式から信号を参照することは、今回は許可してください。
初期値がFPGA初期値、リセット値、シミュレーション初期値のどれに相当するかは、今回確定しないでください。
READMEに「初期値の合成上の意味は未確定」と明記してください。
エラー設計
意味解析エラーはReaderエラー、GateLisp構文エラーと区別してください。
概ね次の構成を想定します。
pub enum CompileError {
    Reader(ParseError),
    GateSyntax(GateParseError),
    Semantic(SemanticError),
}
既存のFrontendErrorを拡張しても構いません。
SemanticErrorには最低限、以下を持たせてください。
•	エラー種別
•	人間向けメッセージ
•	主Span
•	必要に応じて関連Span
重複宣言エラーでは、新しい宣言を主Span、以前の宣言を関連Spanとして保持できる設計が望ましいです。
最低限、以下のエラーを検出してください。
•	module名重複
•	信号名重複
•	未宣言信号参照
•	未宣言assign先
•	inputへのassign
•	registerへのassign
•	同一信号への複数assign
•	未知の演算子
•	演算子の引数数不正
•	算術演算にbitを使用
•	順序比較にbitを使用
•	左右オペランドの型不一致
•	assign右辺と代入先の型不一致
•	if条件がbitでない
•	if分岐型不一致
•	整数リテラル範囲外
•	整数リテラルの型推論不能
•	必要な期待型が得られない式
エラー処理にpanic、unwrap、expectを使用しないでください。ただしテストコード内では使用可能です。
処理順序
各モジュールは概ね次の順序で解析してください。
1.	module IDを割り当てる
2.	module名重複を検査する
3.	port、wire、registerをすべて収集する
4.	SignalIdを割り当てる
5.	信号名重複を検査する
6.	register初期値を型検査する
7.	assign先を名前解決する
8.	assign先の駆動可否を検査する
9.	複数assignを検査する
10.	assign右辺を期待型付きで型検査する
11.	TypedModuleを構築する
宣言順に式の名前解決結果が変化しないようにしてください。

CLI

--sexpr   S-expression ASTを表示
--ast     GateLisp ASTを表示
